# ADR-0009: Constrained, in-house expression language

- Status: Accepted
- Date: 2026-09-23
- Phase: 2

## Context
`Assign`, `If`, `While`, `Switch`, `ForEach`, `Log`, `Throw` and `InvokeWorkflow` need values computed from variables
and arguments. OpenRPA used compiled VB expressions (`ActivityXamlServicesSettings.CompileExpressions = true`,
`OpenRPA/Workflow.cs:541`): full .NET access from workflow files, slow to load, and impossible to validate without
compiling (D1). Workflows will be generated by AI (PRD 8.3) and executed by robots, so expressions are an attack surface.

Options evaluated:

| Option | Security | Determinism | Serialization | Usability | Extensibility | AI generation |
|---|---|---|---|---|---|---|
| Roslyn C# scripting | Arbitrary code; sandboxing .NET is not supported | Depends on code | Source text | High for developers | Unlimited | Easy to generate, unsafe to run |
| Third-party evaluators (NCalc, DynamicExpresso, Jint) | Most allow reflection/member access or need careful hardening; extra dependency | Varies | Text | Good | Good | Good |
| JSON-only operator trees (JsonLogic-style) | Safe | Yes | Native JSON | Verbose for humans | Good | Good |
| **Small in-house language (chosen)** | Only what we implement | Yes | Short text | Familiar C-like syntax | Function whitelist | Good; parse errors are validated before run |

## Decision
Implement a small expression language in `MyRPA.Workflow.Expressions` (BCL only):

- Literals: integers, decimals, `'single'`/`"double"` quoted strings, `true`, `false`, `null`, lists `[a, b]`,
  dictionaries `{'key': value}`.
- Names: workflow variables, arguments, and scoped locals (ForEach item, TryCatch exception).
- Operators: `+ - * / %`, `== != < <= > >=`, `&& || !`, unary `-`, grouping `( )`, index `x[i]`, key access `dict.key`.
- Functions: a fixed whitelist (`len`, `upper`, `lower`, `trim`, `contains`, `startsWith`, `endsWith`, `substring`,
  `replace`, `toString`, `toInt`, `toDecimal`, `toBoolean`, `toDateTime`, `now`, `append`, `keys`, `hasKey`, `isNull`,
  `coalesce`, `abs`, `min`, `max`, `round`). `now()` reads the injected `TimeProvider`.
- Values are limited to the workflow value model (ADR-0010): no CLR member access, no reflection, no type names, no I/O.
- Limits: expression text ≤ 4096 characters, nesting depth ≤ 64.
- Expressions are **parsed during validation** (syntax, unknown functions, arity, unknown names) and stored parsed in
  the model, so they are never re-parsed at run time.
- Strict typing: numeric promotion Int→Decimal only; Int/Int division truncates (C# semantics); checked arithmetic
  (overflow is an error); `+` concatenates when either side is a string; `&&`/`||`/`!` require booleans.

## Alternatives
See the table. Roslyn is rejected outright (ADR-0008). Third-party evaluators may be revisited by ADR if the language
needs to grow substantially.

## Consequences
- MyRPA owns a parser/evaluator (tested in `MyRPA.Workflow.Tests`).
- New functions are added to the whitelist in code; plugins cannot add functions in Phase 2 (revisit in Phase 3).
- In JSON, every expression-kind property that is a string is expression text: a string literal must be quoted
  inside the expression (`"message": "'Hello ' + name"`). JSON numbers/booleans/null are accepted as literals.
